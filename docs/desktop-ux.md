# 桌面端交互改造（Web → 桌面应用）

> 背景：hidane 已是 Wails v3 桌面应用，但界面仍沿用 Web 页面的交互。本文列出改造决定，参考 Paseo 的桌面约定（Electron + 网页渲染，与我们的 Wails + WKWebView 同构）。
> 浏览器模式（`hidane serve`）用同一套界面结构，只是没有原生能力；差异由 `boot().desktop` 决定。

## 1. 真正的缺陷（不只是"不像桌面"）

| 问题 | 原因 | 改法 |
|---|---|---|
| 停止任务、隐藏消息、删除模型服务/规则/记忆/定时在桌面端**点了没反应** | Wails 的 WKWebView 没实现 JS `confirm()` 面板，`confirm()` 直接返回 false | 应用内确认对话框（两种模式通用） |
| 任务完成通知在桌面端不出现 | 嵌入式 WKWebView 没有 Web Notification API | 原生通知：`POST /api/desktop/notify`（Wails notifications 服务，需打包成 .app） |
| 未读数显示在 `document.title` | 桌面窗口标题不是标签页 | Dock 角标：`POST /api/desktop/badge`；浏览器模式仍用标题 |
| 复制依赖 `navigator.clipboard` | 自定义协议页面里不可靠 | 桌面端 `POST /api/desktop/clipboard` |
| "复制链接"（`?at=` 永久链接） | 桌面没有地址栏，链接无处可贴 | 桌面端改为"复制文本"；浏览器模式保留复制链接 |

## 2. 窗口外观

- macOS 隐藏式标题栏（`MacTitleBarHiddenInset`），红绿灯浮在侧边栏左上角；整体是半透明背景。
- 没有独立标题栏：侧边栏顶部和主区域顶部 52px 的工具栏行就是标题栏，可拖动（`--wails-draggable: drag`），按钮、输入框等可交互元素 `no-drag`。
- 侧边栏收起时，主区域工具栏左侧给红绿灯留出约 78px。
- 窗口最小 900×600；大小和位置记在 `runtime/window.json`，下次打开恢复。

## 3. 信息架构

**主窗口**

- 左侧边栏（240px，⌘B 收起，状态记住）：
  - 顶部：拖动区 + 红绿灯留白
  - 操作行：新任务（⌘N）、搜索（⌘K）
  - 导航：会话、待处理（带待处理数）、任务、定时、记忆、工作日志（⌘1–⌘6）
  - **待处理**：等你回答的问题、等你审阅的结果（任务回报之后、你还没回复/标记完成/归档），问题在前；没有就不显示这一组
  - **进行中**：运行中 / 有新进展的工作项列表，带状态点；点开在会话旁的聚焦面板
  - 底部：设置齿轮（提示 ⌘,），浏览器模式下才显示连接状态与退出
- 主区域：52px 工具栏（页面标题 + 页面级操作，可拖动），下面是内容。

**会话与任务的分工**（主对话是入口，不是工作台）

- 主对话的正文是你说的话和 Primary 的回答（快问快答），以及每个任务的卡片；任务自己的回报（worker 的结果，或 Manager 自己动手改过东西之后的回复）在它所属的那条消息下面只占一行，「展开全文」原地展开，全文也在任务的聚焦面板里。直接回答你刚说的话的，照常整段显示。
- 输入框：`@` 选一个或几个任务（默认未归档的，按 等你回答 → 待审阅 → 运行中 → 最近 排序；搜索时也列出已归档的，发消息会重新打开），一句话同时发给它们，不经过模型判断归属；发出后 `@` 清空，不粘滞。聚焦面板开着时，聚焦的任务就是默认收件人。不带 `@` 的话照旧交给 Primary：它直接回答、开新任务，或判断归到已有任务（不确定就问）。
- `/stop` `/done` `/archive` `/reopen`：整条消息就是一个命令时，对 `@` 选中的任务直接执行（停止和归档先确认一次），不发消息、不调模型；`/etc/hosts …` 这类不是命令的照常发送。
- 选了多个任务时，「运行方式」选择器换成一行说明：各任务的运行方式不变。
- Primary 的回答上，右键 / ⋯ 菜单里有「转成任务」：这条消息变成一个新任务，已有的回答作为上下文交给它的 Manager。

**待处理页**（⌘2）

- 待回答：问题全文、已经尝试过什么、可点选的答案（问题带 `options` 时）和一个回答框；回答后离开列表。
- 待审阅：最近的回报、任务所在的仓库与分支，「改动」展开后是这个任务在每个仓库里的提交、未提交的修改和新文件（相对它离开主干的位置，逐文件展开差异）；「标记完成」或「继续交代」（打开会话并对准这个任务）后离开列表。hidane 不替你合并或推送分支。

**设置（独立的全窗口界面，替换主布局，不是弹窗也不是导航里的一页）**

- 打开：⌘, 、菜单「Settings…」、侧边栏齿轮；关闭：Esc、再按 ⌘, 、左上「← 返回」，都回到进入设置前的页面。
- 左侧分区导航，分三组：
  - 应用：通用（语言、完成时通知、Dock 角标）、快捷键（只读列表）、关于（版本、数据目录、在访达中打开）
  - 智能体：角色、模型服务、Agent CLI、安全规则（原「规则」页）
  - 诊断：运行状态（原「状态」页）、事件日志（原「事件」页）
- 右侧：分区标题 + 卡片，卡片内一行一项：左边标签与说明，右边控件。
- 保存：单项设置**改了就生效**（语言、开关、角色的每个下拉、CLI 路径失焦/回车提交）；多字段文档（模型服务表单、新规则）用显式保存。破坏性操作先确认。

## 4. 原生交互

- 菜单：hidane（关于、Settings… ⌘,、隐藏、退出）、File（New Task ⌘N、New Message ⌘L）、Edit（系统）、View（会话/待处理/任务/定时/记忆/日志 ⌘1–6、Search ⌘K、Toggle Sidebar ⌘B、全屏）、Window（系统）。菜单命令以 `hidane:command` 事件交给页面。浏览器模式用页面内快捷键实现同一组命令。
- 命令面板 ⌘K：顶部居中的浮层，输入即搜索全部对话与任务，同时列出命令（跳转页面、新任务、打开设置的各分区）；↑↓ 回车 Esc。
- 右键菜单：消息（复制文本、隐藏、浏览器下复制链接；Primary 的回答还有「转成任务」）、任务卡片与侧边栏任务行（打开、停止、标记完成、归档、在访达中显示工作区）。与悬停时出现的「⋯」按钮共用同一组菜单项。其余区域屏蔽 WebView 默认右键菜单（输入框和选中的文字除外）。
- 图片可直接拖进窗口发送。

## 5. 视觉与细节

- 整个窗口不滚动、不回弹（`html, body { overflow: hidden; overscroll-behavior: none }`），只有内容区滚动。
- 界面元素不可选中（`user-select: none`），只有消息正文、Markdown、代码、输入框、产物内容可选。
- 桌面端按钮用默认箭头光标；只在键盘聚焦时显示焦点环（`:focus-visible`）。
- 13px 正文、12px 辅助文字（见 `frontend/DESIGN.md`），层级靠颜色而不是字号；细滚动条。
- 空状态：居中的一句灰字，最多一个按钮；加载：内联小转圈；toast 顶部居中、短暂。
- 浏览器模式保留 token 门与退出；桌面模式没有。

## 6. 实现说明（与上文的出入）

- 快捷键去重只丢弃**另一来源**在 200ms 内的同一命令（菜单的 key equivalent 与页面 keydown 的双发）；同一来源连按两次是两次操作（自动重复已在 keydown 层过滤）。
- 屏蔽 WebView 默认右键菜单只在桌面模式生效；浏览器模式保留浏览器自己的菜单（我们自己的消息/任务菜单两种模式都有）。"已选中文字"按右键按下**之前**的选区判断：WebKit 右键会先选中光标下的词。
- 设置里 Esc 若焦点在输入框，先让输入框失焦（失焦即保存 CLI 路径/模型），再按一次才离开设置。分区之间切换用 replace，不进浏览器历史。
- 角色设置逐项自动保存时，正在保存期间的新改动会排队，在上一次保存落地后再存，不会被覆盖。
- toast 会自动消失：提示 4 秒，错误 10 秒。
- 「进行中」列出运行中/排队/规划中/子任务进行中的任务，以及打开过但又有新进展的任务；等你回答和待审阅的列在「待处理」。
- 关于 → 数据目录：桌面模式用 `POST /api/desktop/open-data-dir` 在访达中打开，两种模式都可复制路径。
- 拖图片进会话：E2E 用合成的 drop 事件验证（两种模式）；真实 WKWebView 里 Finder 拖入的文件能否以 HTML5 drop 交给页面，取决于 Wails 窗口的文件拖放设置，需要 `make smoke-gui` 时手动确认。
